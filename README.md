# IPAD R01 산업 공정 이상 탐지 실험 결과

작성일: 2026-10-08  
상태: R01 단일 공정에서 수행한 탐색 실험. 최종 논문 성능 및 현장 배포 성능 검증 전.

## 최신 결과

같은 3,042개 공통 평가 프레임에서 전체 화면 DINOv2의 정상 사례 비교 AUROC는 **0.8555**로 CLIP의 0.6002보다 개선됐다. 하지만 정상 기반 임계값에서 정상 오경보율이 **45.70%**여서 실용적인 경고 시스템을 확보한 것은 아니다.

V-JEPA 2 CPU 예비 실험도 완료했다. 같은 96개 공통 sampled endpoint에서 DINO 한 프레임은 0.7990, DINO 시간 특징은 0.7346, V-JEPA는 0.4487이었다. 영상 모델 도입과 DINO+V-JEPA max 결합의 전체 성능 개선은 확인되지 않았다. DINO 시간 특징의 AP는 0.6754로 한 프레임 0.6293보다 높았지만 AUROC는 낮았다.

- [DINOv2 / V-JEPA 후속 실험 분석](reports/2026-10-08-followup-results.md)
- [DINOv2 원본 결과 JSON](results/dinov2_report.json)
- [V-JEPA 원본 결과 JSON](results/vjepa_report.json)

0.8555와 0.7990은 평가 시점 및 정상 기준 생성 관측 수가 다르므로 직접 비교하지 않는다. 후속 실험 분석에는 평가 범위, 영상별 표본 수, 경고 기준, 실패와 미검증 주장을 함께 기록했다.

## 전기 CLIP 비교 실험의 결과

아래 1–14절은 초기 CLIP 및 공개 IPAD 코드 검증 단계의 기록이다. 최신 인코더·시간 표현 비교의 결론은 위 후속 실험 분석을 참고한다.

컨베이어 장면에서 전체 화면, 객체 외관, 객체 움직임, 객체 외관과 움직임의 결합을 비교했다. 기존 PCA 점수에서는 전체 화면 방식이 가장 좋았다. 객체 외관과 움직임을 분리하고 단순 결합하는 것만으로는 성능이 개선되지 않았다.

동일한 특징을 가장 가까운 정상 사례와 비교하도록 바꾸자 객체 외관·움직임·결합 방식의 AUROC가 모두 개선됐다. 특히 일부 영상에서는 움직임 정보가 이상 구간을 구분하는 데 효과적이었다. 다만 전체 성능은 전체 화면 PCA 기준 모델을 넘지 못했고, 정상 영상에서 정한 경고 기준의 탐지율도 낮았다.

따라서 현재 근거는 **정상 비교 방식과 영상별 이상 특성을 분석할 필요가 있다**는 것이다. 객체 중심 구조의 우수성, LLM 제거 효과, 최종 실시간 시스템의 성능은 아직 입증하지 않았다.

## 1. 연구 목적과 질문

초기 목적은 정상 산업 공정 영상만으로 정상 모습을 모델링하고, 테스트 영상에서 외관과 동작의 이상을 탐지하는 것이다.

이번 실험은 다음 질문을 확인하기 위해 구성했다.

1. 전체 화면보다 제품 객체에 집중하면 이상 탐지가 좋아지는가?
2. 객체의 짧은 움직임 기록은 외관만으로 놓치는 이상을 구분하는가?
3. 객체 외관과 움직임을 결합하면 성능이 개선되는가?
4. 동일한 특징에서도 정상과 비교하는 방식에 따라 결과가 달라지는가?

## 2. 데이터셋과 정답 구성

IPAD의 실제 컨베이어 장면인 R01을 사용했다.

| 구분 | 영상 수 | 프레임 수 | 용도 |
|---|---:|---:|---|
| Training | 34 | 7,808 | 정상 기준 생성 및 정상 데이터 기반 보정 |
| Testing | 15 | 3,685 | 이상 점수 계산 및 평가 |

데이터는 영상별 프레임 이미지 폴더로 제공된다.

```text
R01/
├── training/frames/01 ... 34/*.jpg
├── testing/frames/01 ... 15/*.jpg
└── test_label/001.npy ... 015.npy
```

`training/01`과 `testing/01`은 별개의 영상이며, 번호가 같다고 대응되는 쌍은 아니다. 학습 영상은 모두 정상이다. 테스트 라벨은 프레임별 `0=정상`, `1=이상`이다.

| 테스트 영상 | 전체 프레임 | 이상 프레임 |
|---|---:|---:|
| 01 | 230 | 141 |
| 02 | 256 | 127 |
| 03 | 409 | 195 |
| 04 | 191 | 90 |
| 05 | 290 | 92 |
| 06 | 233 | 220 |
| 07 | 231 | 195 |
| 08 | 235 | 194 |
| 09–15 | 1,610 | 0 |
| 합계 | 3,685 | 1,254 |

현재 사용한 라벨에는 외관·속도·정지 등 이상 종류의 구분이나 객체 위치 정답이 없다. 따라서 외관 및 움직임 모듈의 성능을 비교했지만, 이상 유형별 탐지 성능을 측정한 것은 아니다. 원본 FPS도 확인되지 않아 움직임은 원본 프레임 간 이동량으로 표현했다.

## 3. 초기 설계와 범위 변경

초기 설계는 다음과 같다.

```text
정상 영상
  → VLM/LLM으로 객체 vocabulary 및 공정 단계 정의
  → GroundingDINO + tracking
  → 객체 중심 이미지 특징 및 상태 표현
  → 공정 단계별 정상 subspace / 공정 순서 모델
  → 외관·동작·공정 이상 점수
```

초기 구현에서 VLM JSON 출력 오류와 Tesla T4의 GPU 메모리 부족을 경험했다. 또한 R01에 의미 있는 공정 단계를 부여하고 검증하는 문제가 해결되지 않았다. 현재 비교 실험은 범위를 줄여 LLM 생성, 공정 단계 분류, 단계별 subspace, 공정 순서 모델을 제외했다.

CLIP의 이미지 인코더는 계속 사용했다. 언어 모델을 제거한 것과 이미지 특징 추출기를 제거한 것은 다르다. LLM/phase 포함 모델의 유효한 성능 결과가 없으므로, 이번 결과는 이 모듈들의 제거 효과를 증명하지 않는다.

## 4. 현재 모델의 입력과 출력

### 4.1 프레임 처리

모든 원본 프레임을 순서대로 처리했다. 관심 영역은 정규화 좌표 `[0, 0.22, 1, 0.76]`의 컨베이어 작업 영역으로 설정했다.

| 단계 | 입력 | 출력 |
|---|---|---|
| 객체 검출 | 관심 영역 이미지 + `small object` 텍스트 | 검출 사각형과 신뢰도 |
| 추적 | 현재·이전 프레임의 사각형 | 객체 track ID 및 연속 관측 기록 |
| 전체 화면 특징 | 전체 프레임 | 정규화된 CLIP 512차원 특징 |
| 객체 외관 특징 | 사각형 주변 5% 여백을 포함한 객체 crop | 정규화된 CLIP 512차원 특징 |
| 움직임 특징 | 같은 객체의 연속 10프레임 기록 | 위치·크기·이동량을 묶은 58차원 특징 |
| 정상 비교 | 테스트 특징 + 정상 기준 | 객체 및 프레임별 이상 점수 |

GroundingDINO는 프레임별 검출기로 사용했으며 정상·이상을 판단하지 않는다. 추적은 사각형 겹침에 기반한 greedy IoU 연결이다. 외관 인코더는 `openai/clip-vit-base-patch32`이며 가중치를 고정했다. 신경망을 R01에 맞춰 미세 조정하지 않았다.

검색어와 관심 영역은 정상 프레임 미리보기를 보고 수동으로 결정했다. 정상 미리보기에서 5개 후보 검색어를 비교한 뒤 `small object`를 사용했다. 자동 vocabulary 발견 모델이나 최적 검색어 탐색 결과로 해석하지 않는다. 이전 R01 테스트 결과를 이미 본 상태의 탐색 실험이라는 점도 유지한다.

### 4.2 움직임 기록과 출현·소멸 처리

움직임 특징은 각 프레임의 정규화된 중심 위치와 사각형 크기 `10×4`, 연속 프레임의 중심 이동량 `9×2`로 구성된다.

10프레임이 모이면 첫 움직임 점수가 나온다. 이후에는 `1–10 → 2–11 → 3–12`처럼 한 프레임씩 이동하는 창을 사용한다. 미래 프레임은 사용하지 않는다.

제품의 출현·소멸 자체는 이상으로 처리하지 않는다. 추적이 끊기거나 간격이 생기면 움직임 기록을 초기화한다. 객체를 못 찾았거나 움직임 기록이 부족한 경우 점수는 미관측으로 남기며, 0점이나 정상 판정으로 대체하지 않는다. D는 외관만 관측되면 외관 점수를 사용할 수 있으며, 부분 관측 여부를 기록한다.

움직임 모듈은 사각형의 위치·크기 변화를 표현한다. 물체 내부의 미세한 변형이나 의미적 작업 순서를 직접 이해하는 모듈은 아니다.

### 4.3 정상 학습 데이터 분할

| 정상 영상 번호 | 사용 목적 |
|---|---|
| 01–27 | 정상 기준 생성 |
| 28–30 | 점수 스케일 보정 |
| 31–34 | 경고 임계값 설정 |

점수 스케일과 임계값은 각 그룹의 정상 점수 99분위수로 설정했다. 이 분할은 이번 실험의 설정이며 IPAD 논문의 공식 분할이라고 주장하지 않는다. 테스트 라벨은 기준 생성·보정·임계값 설정에 사용하지 않았다.

### 4.4 비교한 네 방식

| 방식 | 사용하는 정보 | 프레임 점수 |
|---|---|---|
| A | 전체 화면 외관 | 전체 화면 특징의 이상 점수 |
| B | 객체 외관 | 관측된 객체 외관 점수의 최댓값 |
| C | 객체 움직임 | 관측된 객체 움직임 점수의 최댓값 |
| D | 객체 외관 + 움직임 | 정상 데이터로 스케일을 맞춘 B·C 중 사용 가능한 점수의 최댓값 |

A와 B는 입력 범위, 관심 영역 제한, 검출 및 crop의 영향이 함께 다르다. 따라서 A–B 차이를 순수한 객체 crop의 효과라고 분리해서 해석할 수는 없다.

## 5. 정상과 비교하는 두 방법

### PCA residual

정상 특징에서 자주 나타나는 변화 방향을 PCA로 저장한다. 테스트 특징을 이 정상 공간으로 표현했을 때 설명되지 않고 남는 크기를 점수로 사용한다. 외관 PCA rank는 16, 움직임 rank는 4다. 움직임은 정상 학습 특징의 평균·표준편차로 표준화하며, 위치/크기와 이동량에 각각 최소 표준편차를 적용한다.

이 방법은 정상 공간 내부에서 발생하는 드문 변화에 낮은 점수를 줄 수 있다. 이번 구현은 PCA에 기반한 탐색 기준 모델이며, 공식 SubspaceAD 재현은 아니다.

### Nearest normal example

동일한 특징과 정상 영상 분할을 유지하고, 정상 학습 사례 중 가장 가까운 특징과의 거리를 점수로 사용했다. 외관은 정규화된 CLIP 특징, 움직임은 기존 방식과 같은 정상 표준화 특징을 사용했다. PCA 투영은 점수 계산에 사용하지 않는다. 정상 사례를 축약한 prototype 대신 정상 학습 관측 전체를 저장했다.

거리 기반 점수에서도 기존 방식과 동일한 정상 그룹으로 스케일 및 임계값을 다시 보정했다. 테스트 점수를 보고 임계값을 선택하거나 점수 부호를 뒤집지는 않았다. 이 방식은 비교를 위한 기존 거리 기준 모델이며 새로운 알고리즘이라는 주장은 하지 않는다.

## 6. 평가 기준

AUROC는 이상 프레임이 정상 프레임보다 높은 점수를 받는 정도를 평가한다. `1`에 가까울수록 좋고 `0.5`는 무작위 구분 수준이다. 정확도 또는 실제 경고 탐지율과 동일하지 않다.

AP는 이상 프레임을 높은 점수부터 찾아가는 성능을 평가하며, 이상 프레임 비율에 영향을 받는다. 전체 영상의 프레임을 합친 지표와 영상 내부의 지표를 함께 확인했다.

공정별 객체 검출 및 추적 누락 때문에 네 방식의 주 비교는 모두 점수가 존재하는 **동일한 3,042프레임**에서 수행했다.

| 평가 항목 | 값 |
|---|---:|
| 전체 테스트 프레임 | 3,685 |
| 공통 평가 프레임 | 3,042 |
| 공통 평가 비율 | 82.55% |
| 공통 평가 프레임 중 이상 | 1,182 |
| 공통 평가에서 제외된 이상 | 72 |
| 객체 외관 점수 관측 비율 | 91.51% |
| 움직임 점수 관측 비율 | 82.55% |

관측 비율은 정확도가 아니다. 검출이 맞는지 확인할 객체 정답도 없다. 실제 경고의 `recall_all`에서는 점수가 없는 이상 프레임도 놓친 것으로 계산했다. 관측 가능한 프레임만 평가한 지표는 각 방법마다 평가 집합이 다르므로 주 비교로 사용하지 않았다.

## 7. 전체 결과

### 7.1 동일 프레임 AUROC 및 AP

| 방식 | PCA AUROC | 정상 사례 AUROC | PCA AP | 정상 사례 AP |
|---|---:|---:|---:|---:|
| A: 전체 화면 | **0.6853** | 0.6002 | **0.4907** | 0.4193 |
| B: 객체 외관 | 0.5629 | **0.6309** | 0.4791 | **0.5195** |
| C: 객체 움직임 | 0.4623 | **0.5991** | 0.3407 | **0.4419** |
| D: 객체 외관 + 움직임 | 0.4935 | **0.6317** | 0.3670 | **0.4534** |

정상 사례 비교는 PCA 대비 B의 AUROC를 약 0.0680, C를 0.1368, D를 0.1382 높였다. 그러나 전체 화면 PCA의 0.6853을 넘지는 못했다. 정상 사례 방식 내부에서도 D와 B의 AUROC 차이는 약 0.0008이며, D의 AP는 B보다 낮다. 따라서 결합의 명확한 이득이 확인됐다고 주장하기 어렵다.

### 7.2 정상 데이터 기반 경고 기준의 결과

전체 이상 프레임 1,254개를 분모로 한 탐지율과, 각 방식이 점수를 낸 정상 프레임 중 오경보율이다.

| 방식 | PCA 이상 탐지율 | 정상 사례 이상 탐지율 | PCA 정상 오경보율 | 정상 사례 정상 오경보율 |
|---|---:|---:|---:|---:|
| A | 0.00% | 0.00% | 1.19% | 1.07% |

순위 성능이 좋아진 것과 실제 경고가 잘 작동하는 것은 다르다. 현재 임계값에서는 많은 이상을 놓친다. 표의 각 방식은 서로 다른 정상 기반 임계값과 관측 집합을 사용하므로 동일 오경보율에서의 성능 비교로 해석하지 않는다.

## 8. 실패 장면 분석

원래 PCA 실험에서 오경보와 놓친 이상을 선택해 `error_cases.png`를 생성했다. 이 이미지의 빨간 사각형은 검출된 객체 위치이며 이상 위치의 정답이 아니다.

테스트 02의 진입 순간에 높은 점수가 발생했다. 초기 해석에서 왼쪽의 일부만 보이는 물체를 잘못된 검출 대상으로 단정했지만, 사용자 확인에 따르면 화면에 진입하는 같은 제품이다. 따라서 **잘못된 객체 검출이라는 결론은 철회**했다.

현재 가설은 제품이 일부만 보이는 정상 진입 외관과, 진입 중 사각형 위치·크기 변화가 높은 점수를 만들 수 있다는 것이다. 추적 ID 변경 또는 동작 오류 여부는 정지 이미지로 확정하지 않았다. 인접 프레임을 확인해야 한다.

또한 실제 이상 장면에서 제품을 검출했는데도 탐지하지 못한 사례가 있다. 검출 성공만으로 이상 탐지가 보장되지 않는다. 이 사례 이미지가 현재 정상 사례 비교 방식의 실패 사례까지 대표하는 것은 아니다.

## 9. 기존 실험과 IPAD 실행 검증

| 실험 | 평가 범위 | AUROC | AP | 해석 |
|---|---|---:|---:|---|
| 초기 frozen CLIP + 전체 화면 PCA | 테스트 전체 3,685프레임 | 0.6730 | 0.4269 | 초기 기준 모델 |
| 현재 PCA A | 테스트 전체 3,685프레임 | 0.6713 | 0.4249 | 초기 기준 모델과 유사 |
| 현재 PCA A의 공통 프레임 결과 | 3,042프레임 | 0.6853 | 0.4907 | A/B/C/D의 주 비교 기준 |
| IPAD 공개 코드 수정 후 pilot | 중심 프레임 3,460개 | 0.7704 | 0.5252 | 짧은 실행 검증, 정확한 논문 재현 아님 |

초기 전체 화면 PCA의 정상 기반 경고 기준에서는 이상 탐지율이 0%, 정상 오경보율이 약 1.19%였다.

IPAD 공개 코드와 공급 ZIP에서 학습 가중치를 확인하지 못했다. 코드의 메모리 모듈 및 실행 문제를 수정한 뒤, random initialization에서 1회 학습·저장·복원 smoke test와 200-step pilot을 수행했다. smoke test는 통과했으며 성능 검증은 아니다.

Pilot은 batch size 1, 입력 `[1, 3, 16, 256, 256]`, Tesla T4, float16 AMP를 사용했다. 200 step은 약 7,298개 가능한 학습 clip 기준 약 0.027 epoch에 해당하는 분량이며, 모든 clip을 한 번 처리한 학습이 아니다. 50 epoch를 완료하지 않았다.

수정 모델의 전체 파라미터는 약 263.48M이고 period head는 약 226.06M이다. 논문에 제시된 약 35.9M 모델과 차이가 있어 논문 모델의 정확한 재현이라고 부르지 않는다. Pilot에서는 여러 영상의 이상 구간 점수가 정상보다 낮았고, 전체 AUROC만으로 시간적 탐지 성공을 주장할 수 없었다.

IPAD pilot은 중심 프레임 예측에 미래 프레임을 사용하고 테스트 전체 점수 정규화도 적용했다. 현재 객체·동작 실험과 평가 조건이 다르므로 수치만으로 직접 우열을 정하지 않는다. 이 검증은 온라인·실시간 시스템의 증거가 아니다.

## 10. 실행 환경과 처리 비용

| 항목 | 관측값 |
|---|---|

| 동작 창 | 연속 과거 10프레임 |

특징 추출 시간은 로컬 JPG 읽기, 검출, 추적, CLIP을 포함하고 다운로드·해시 계산·캐시 저장 등은 제외한다. 캐시 실험 시간은 캐시 로딩 이후의 해당 방식 실행 시간이며 전체 노트북 소요 시간이 아니다. 이 두 시간을 근거로 정상 사례 방식이 일반적으로 더 빠르다고 주장하지 않는다.

캐시 저장 덕분에 같은 특징의 추가 점수 비교는 전체 검출을 다시 수행하지 않고 진행했다. 원본 FPS와 실제 end-to-end 지연을 검증하지 않았으므로 실시간 산업 현장 구현이라는 주장은 하지 않는다.

## 12. 다음 실험 우선순위

1. **실제 이상 내용과 추적 확인:** 03·05와 07·08의 연속 프레임, 정상 진입·퇴장 구간을 확인한다. 실제 이상 종류, 사각형 변화, 추적 연결, 점수를 같이 본다.
2. **정상 진입·퇴장에 대한 점수 안정성 확인:** 정상 데이터에서 부분 가시성 및 경계 접근을 구분할 수 있는지 살펴본다. 경계 프레임을 단순 제거해서 성능을 높이는 대신 관측 비율·전체 이상 탐지율을 함께 평가한다.
3. **정상 점수 보정 분석:** 정상 보정 영상과 정상 테스트 영상의 점수 분포를 비교한다. 임계값 수정은 정상 데이터만으로 설계하며 테스트 정답을 보고 맞추지 않는다.
4. **특징 표현 비교:** 영상 내용을 확인한 뒤 현재 위치·크기 기록에 필요한 동작 정보가 포함되는지 판단한다. 필요하면 이미지 인코더 및 시간 특징을 하나씩 바꾸는 비교를 수행한다.
5. **다른 공정에서 확인:** 개선안을 고정한 뒤 다른 장면에서도 같은 조건으로 평가해 R01 특화 결과인지 확인한다.

현 단계에서는 모듈을 많이 추가하는 것보다 효과가 있는 조건과 실패하는 조건을 설명하는 것이 우선이다. 정상 진입·퇴장의 부분 관측과 실제 동작 이상을 구별하는 개선안은 가능한 연구 방향이지만, 독창성과 효과는 별도 검증이 필요하다.

## 13. 회의에서 사용할 결론

> R01에서 전체 화면, 객체 외관, 객체 움직임 및 결합 방식을 비교했다. 단순 객체 분리와 PCA 점수 결합은 전체 성능을 개선하지 못했다. 동일한 특징을 정상 사례와 비교하면 객체 기반 방식의 성능이 개선됐고, 일부 영상에서는 움직임 특징이 이상 구간을 잘 구분했다. 그러나 영상별 편차와 낮은 경고 탐지율이 남아 있다. 다음 단계는 실제 이상 유형과 정상 진입·퇴장을 확인해 동작 표현 및 정상 점수 보정을 개선하는 것이다.

## DINOv2 후속 비교 실행

기존 검출 사각형과 추적을 재사용하고 외관 인코더만 frozen DINOv2-Small로 바꾸는 후속 실험을 실행했다. 같은 3,042개 평가 프레임에서 전체 화면 AUROC는 PCA 0.8270, 정상 사례 비교 0.8555로 개선됐다. 전체 테스트 3,685프레임에서 정상 사례 방식은 0.8352다. 다만 정상 기반 임계값의 정상 오경보율이 45.70%여서 실용적인 경고 기준은 아직 확보하지 못했다. 전체 점수만으로 모든 영상의 시간적 이상 탐지가 개선됐다고 주장하지 않는다.

- [Colab 실행 안내](docs/dinov2_comparison.md)
- [독립 실행 스크립트](experiments/IPAD_DINOv2_Comparison.py)

원래 CLIP 특징과 새 DINOv2 특징을 동일 정상 영상 분할 및 동일 평가 프레임에서 PCA / 정상 사례 거리 방식으로 비교한다. 동작 특징은 변경하지 않는다.

## V-JEPA 2 CPU 시간 특징 비교

사전학습 V-JEPA 2 인코더로 과거 16프레임의 영상 특징을 추출했다. CPU 비용을 줄이기 위해 32프레임 간격의 동일 시점에서 DINO 한 프레임, DINO 시간 특징, 기존 객체 좌표, V-JEPA 및 DINO+V-JEPA를 비교했다. **실행 완료, 결과 및 한계는 후속 실험 분석에 기록했다.** sparse endpoint 결과와 기존 전체 프레임 결과를 직접 비교하지 않는다.

- [CPU 실행 안내](docs/vjepa_cpu.md)
- [V-JEPA 2 독립 실행 스크립트](experiments/IPAD_VJEPA_CPU.py)

이미 저장된 객체 검출·추적 및 DINOv2 특징은 재사용한다. 영상 인코더 입력은 고정된 전체 화면 crop이며 객체 중심 V-JEPA 실험은 아니다. 완료된 영상 구간마다 특징을 저장해 중단 후 재개할 수 있다.
